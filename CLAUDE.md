Local-first university scheduling + workforce + recruitment assistant (Farq hackathon, university-operations track).
Spec: `docs/MIZAN - Project Documentation v3.md` (six agents, deterministic tools, human approval). - Tooling: `.gitattributes` (py/md LF, cmd/ps1 CRLF), `.github/workflows/verify.yml`, pinned `npx.cmd --yes pnpm@12.9.1 run build`.
- Faculty week solver (2026-10-05): 1,499 enrollment patterns vs 20 in baseline → full model (~32k vars) spent 25–45 s in presolve → UNKNOWN. Fix: `backend/lns.py` large-neighbourhood search, used by `solver.optimize` when rules is None, movable is None and patterns > `LNS_PATTERNS` (200). Rounds free ~24 sections (×1.5 at local optimum, max 96), fold fixed sections into constants, encode each merged pattern's weekly gap/days as exact tables over its free sections' option combos (linear 0/1 objective; min/max encoding was too weak to prove even 48-decision rounds), probing off. `Context.score` mirrors the full objective exactly (tests in `tests/test_lns.py`). Measured: 5 s → 83,473,380 = full model's proven optimum (663 h, 5 changes, 20 worse); plans in 15 s: time_saved 1,251 h, fewest_changes 325 h/1 change, balanced 870 h. Status always FEASIBLE (unproven). Baseline/rule/own-section runs unchanged.
- Why the baseline timetable puts each cohort on two days: `fixtures.generate` uses days `[g%3, g%3+2]` on purpose (deliberately bad baseline); `time_saved` also minimizes campus days, so it keeps classes compact.

## Fine-tuned coordinator (done, live since 2026-09-24)
- Protocol frozen in `training/coordinator/PROTOCOL.md`: Qwen3-8B NF4, attention-only LoRA r8/α16, 2 epochs, 480 train / 60 val / 120 test synthetic cases (balanced EN/AR). Runner: `run_experiment.ps1`; report: `coordinator_report.md`.
- Paired NF4 test: pretrained 73/120 pass → fine-tuned 116/120 (44 fixed / 1 broken). Epoch 2 selected (val loss 0.0258). Training took 12.6 min.
- Deployed (live GGUF + production JSON schema, `deployed_eval.py`), re-measured 2026-10-04 with three arms after an expert review flagged the prompt/adapter confound: base + old prompt 75 → base + training prompt 96 (repeat 97) → fine-tuned 106 (repeat 105). Fine-tuning alone: 14 fixed / 4 broken, p≈0.03. The old "111 vs 75" is superseded; never quote it. `deployed_ablation.md`, `deployed_eval_summary.json`. Test log: `docs/test-log-2026-10-04.txt`.
- Remaining errors: says "recommend" for unchanged final candidates (harmless in app — `run_collaboration` computes disposition itself) and sometimes ignores "start with teaching capacity".
- Adapter applies ONLY to coordinator calls: `local_model.structured()` always sends per-request `lora` scales (1.0 for coordinator, 0.0 otherwise); coordinator uses `COORDINATOR_TUNED_PROMPT` (exact training prompt) + compact JSON. Rollback: env `MIZAN_COORDINATOR_ADAPTER=0`.
- Caveat: test set comes from the same generator as training data → measures in-workflow generalization only. More epochs NOT recommended; next is varied data + a hand-written messy EN/AR test set.
- Fixes made along the way: training venv torch had been overwritten with 2.14.0+cpu (repaired to 2.8.0+cu128); `train.py` lm_head dtype mismatch fixed with a forward pre-hook; `benchmark.grade` catches AttributeError.
